============================================================
2. ROLE OF TEACHER / MENTOR
============================================================

The Teacher/Mentor is the academic support role.

The Teacher/Mentor is responsible for helping students learn
and resolving academic doubts.

The Teacher/Mentor should be able to:

1. Review student doubts
2. Approve valid doubts
3. Reject invalid/bogus/irrelevant doubts
4. Provide a rejection reason
5. Answer approved doubts
6. Continue doubt discussions
7. Mark doubts as resolved
8. View students relevant to their assigned classes
9. Upload academic learning materials
10. Manage materials they are responsible for
11. Participate in the student community
12. Review flagged community content
13. Issue warnings to students when necessary
14. Publish announcements
15. View notifications
16. View basic contribution/activity statistics
17. Manage their own profile/settings


============================================================
3. IMPORTANT ROLE DISTINCTION
============================================================

The Teacher/Mentor is NOT an Admin.

Teacher/Mentor:

- Handles academic interaction
- Reviews doubts
- Answers doubts
- Supports students
- Uploads academic material
- Moderates student community
- Publishes academic announcements

Admin:

- Manages teachers
- Manages students
- Manages classes/divisions
- Manages platform structure
- Has system-level oversight

Do NOT give the Teacher/Mentor unnecessary Admin capabilities.

For example, Teacher/Mentor should NOT normally:

- Delete platform users
- Create system-wide roles
- Manage all teachers
- Manage all classes
- Change platform settings
- Access unrelated administrative reports


============================================================
4. TEACHER VS MENTOR
============================================================

For the frontend prototype, Teacher and Mentor can use a
SHARED INTERFACE.

The role can be called:

"Teacher / Mentor"

This avoids creating two completely separate dashboards.

However, the system should allow for different permissions
later.

For example:

Teacher:

- Assigned classes
- Assigned subjects
- Student doubts
- Academic materials
- Announcements

Mentor:

- Assigned doubt tickets
- Student support
- Community participation
- Academic responses

The exact backend permission model will be decided later.

For the frontend prototype, use a unified Teacher/Mentor portal.

============================================================
